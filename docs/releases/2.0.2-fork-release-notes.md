# OpenLess 2.0.2 — primeira Stable do fork

Repositório e atualizações: https://github.com/flavioacv/openless/releases

Esta é a primeira versão própria do fork. Não existe uma Stable pública anterior deste repositório para comparação. A base é a main após a [PR #1](https://github.com/flavioacv/openless/pull/1), preservando português, Opus, inserção rica e demais correções locais. Não representa incorporação integral da Beta atual do oficial.

## Funcionalidades e melhorias

- Interface em português e personalizações existentes preservadas (commit `1126febc`, autoria registrada no histórico Git).
- Opus e preferências de inserção rica preservados (commit `ff5f78e9`, autoria registrada no histórico Git).
- Canal padrão Stable para esta versão compilada; preferências de canal explicitamente selecionadas pelo usuário continuam respeitadas.

## Arquitetura

Sem alteração das dependências ou da estrutura Core/Host nesta preparação. As versões npm/Tauri/Cargo foram sincronizadas para `2.0.2`. A chave pública do atualizador foi substituída por uma própria, idêntica em desktop e Android.

## Build e distribuição

- Os endpoints Stable/Beta e os downloads usam exclusivamente releases de `flavioacv/openless` (com o fallback proxy já existente).
- O fork possui par de assinatura próprio; a chave privada permanece fora do código e cadastrada nos secrets do GitHub Actions.
- Stable consulta `releases/latest`; versões Beta usam manifestos separados. Novas versões devem incrementar SemVer, e a Stable deve ser publicada como latest, nunca como prerelease.
- A notificação existente consulta ao iniciar e a cada hora, respeitando a preferência do usuário.
- O GitHub Actions está impedido de iniciar jobs por pendência de cobrança da conta. Este registro permanece em draft até haver artefatos, verificação e aprovação para publicação.
- Sem certificado Apple Developer ID/notarização configurado, o pacote macOS usa assinatura ad-hoc. A assinatura de atualização Tauri é independente e utiliza o par próprio do fork.
- Linux, iOS, Android, Windows e macOS Intel só devem ser anunciados como disponíveis quando seus respectivos pacotes forem realmente anexados e validados. Um build local Apple Silicon não comprova suporte testado às outras plataformas.

## Instalação e atualização

Instalações que ainda consultam o oficial precisam instalar manualmente a primeira versão deste fork. Após instalar este pacote com sua chave própria, as próximas versões publicadas no nosso repositório poderão ser reconhecidas e verificadas pelo app. Para permanecer na Stable, selecione esse canal em Configurações → Sobre.

Não basta editar o título ou criar uma release vazia: os binários devem conter a versão correta e a chave própria, e a release publicada deve incluir o manifesto da plataforma e seu pacote com assinatura válida. Não publicar este draft sem os arquivos correspondentes.

## Verificação

Testes de preparação Stable/Beta, preservação de dependências, consistência de chave desktop/Android e manifestos do fork aprovados localmente. Build nativo e aceitação de instalação/atualização são verificações separadas; o status real dos artefatos deve ser conferido antes de publicar.
